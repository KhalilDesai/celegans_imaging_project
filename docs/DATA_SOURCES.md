# Where every input comes from

The port uses five kinds of inputs. Only the first comes from Zenodo.

| # | What | Source | Where in the repo |
|---|---|---|---|
| 1 | Per-gene parameter table, gene index, published reference outputs | **Zenodo record 7761843** (published 2024-03-22; its README is dated 2023), CC-BY-4.0 | `data/` (verbatim, SHA-256 in `data/README.md`) |
| 2 | The original analysis code | **GitHub `regreen/EMBD_public`** (Python 2.7), forked into this repo | `development/`, `embryos_analyze/`, `embryocrop/` (unmodified) |
| 3 | Constants and lists hardcoded *inside* that code | GitHub code (2), not Zenodo | ported verbatim into `src/embd/` |
| 4 | Files the original read from the lab server but which are not public | **Reconstructed** by the port from (1) | built at run time (`embd_data`) |
| 5 | "Golden" reference outputs | **Generated by us**: the original code (2) run unmodified on the Zenodo table (1) | `tests/golden/` |

## 1. Zenodo (doi:10.5281/zenodo.7761843)

Only the small summary archive is copied (`EMBD_summary_readme_files.zip`, 1.7 MB, fetched 2026-10-08):

| File | Used as |
|---|---|
| `All_genes_mySQL_table.xlsx` | **The pipeline input**: a dump of the lab's MySQL `genes` table (513 conditions + control; per-gene medians of the image-analysis parameters, plus annotations and manual scoring). See `PARAMETER_TABLE.md`. |
| `Index_EMBD_ID_Gene_names.xlsx` (and an identical `A Index…` copy) | EMBD ID ↔ sequence name ↔ gene name. Source of `gene_key.csv` (row 4 below). |
| `all_best_matches_05192022.xlsx` | Published top-10 matches (May 2022 run). Secondary check only. |
| `EMBD0001_0504_…_052422.csv` | Published top hits / reciprocal matches / auto-descriptions (May 2022). Secondary check only. |

Not copied (≈ 19.4 GB): per-condition composite movies, top-hit and reciprocal-hit movies, UMAP images and
hits matrices. Per-embryo measurements and raw image stacks are not in the record, which is why the image
analysis cannot be re-run from public data.

**Dates matter.** The table is a 2023 snapshot; the published reference outputs came from the April/May 2022
runs. A few genes were reprocessed in between (EMBD 1, 478, 181–185, 191, 363), so the published files differ
slightly from what the code produces on this table (DECISIONS X2/X3, Q10). The maintainer chose the 2023 table
as the baseline (Q10, X4).

## 2–3. The GitHub code and the numbers inside it

`regreen/EMBD_public`, accompanying Green et al. 2024, *Cell* 187:3141. Besides the logic, it hardcodes
scientific inputs that exist nowhere else:

- wild-type control means and spreads across RNAi conditions (`RNAiClass.setOrigin` → `src/embd/_rnai_constants.py`, byte-checked; DECISIONS R1);
- the parameter sets, including the 2018 optimal set (`params_use_assign.py`; see `PARAMETER_SELECTION.md`);
- the 17 hand-curated phenotype groups and their descriptions (`groupAssesment.py`), and the UMAP overlay groups (`makeUMAPs_V2.py`).

## 4. Reconstructed (not public)

| Original input | Port's replacement |
|---|---|
| MySQL server (`genes`, `pad_rank`, `pair_lookup`) | SQLite file built from the Zenodo table (`src/embd_data/mysql_emulation.py`) |
| `Z:/gene_key.csv` on the lab server | built from the Zenodo index (`embd_data.sheet.write_gene_key`); Excel-mangled dates such as `apr-1` → 2022-04-01 are converted back (DECISIONS A9, A16) |
| per-gene pickles, `version` column | not needed: the data layer supplies a version so the image-analysis path is never triggered (A4) |

## 5. Golden outputs

Produced in Phase 1 by `legacy_baseline/` (Python 2.7 in Docker, original code unmodified, MySQL replaced by the
SQLite emulation), from the Zenodo table. They are the regression reference for the port (DECISIONS X4 option a).
Provenance (image digests, package versions, input checksum) is in `tests/golden/provenance.json`.
