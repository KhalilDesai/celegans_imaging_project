# Controls and normalisation: what the code does, and how sound it is

Written 2026-10-26. An assessment of the **original** method; the port reproduces it unchanged. Numbers are for
the optimal parameter set (17 GLS + 24 MS) on the 2023 Zenodo table, and are regenerated by
`tools/assess_controls.py`. Marked **(inferred)** where the code does not say so explicitly.

## What the code uses as the control

There is **one fixed reference point**, the average wild-type embryo, and every gene is placed relative to it
(`RNAiClass.setOrigin` / `setNDPosition`):

$$\text{position}_p = \frac{\text{gene value}_p - \text{controlOrigin}_p}{\text{rnaiStd}_p}$$

| Quantity | What it is | Where it comes from |
|---|---|---|
| `controlOrigin` | per-parameter **mean over individual control embryos** (RNAi condition 0, not dead) | `get_control_origin()` in the original `development/RNAiClass.py` reads the per-embryo `embryos` table; the result is pasted into the code as constants, now `src/embd/_rnai_constants.py` (DECISIONS R1). That this function produced the constants is **(inferred)**; LAB_QUESTIONS #9 asks. |
| `rnaiStd` | per-parameter spread **across RNAi conditions**: the normalisation scale | hardcoded alongside; how it was computed is not in the code **(inferred: across RNAi embryos, as `get_all_params(..., rnai=None)` returns)** |
| `controlStd` | spread across control embryos | hardcoded; **not used by PAD** (only `stdV`). The code keeps a commented-out alternative that divides by it. |
| gene value | per-parameter **median** over the gene's usable embryos, each parameter separately | image-analysis step (not public): only non-moving embryos if more than one failed to move (`asignUse`); per parameter, only embryos whose fit passed `checkGoodParam` (`calcAverageParams`) |

The `embd_id = 0` row of the Zenodo table is the same origin written back (`write_controlAvg_mysql`): it agrees
with the hardcoded constants to within **0.125** RNAi-spread units on all 41 parameters.

Note: `ControlClass` (control as a gene, used for that row) takes the first 20 imaging folders and only moving
embryos, while `get_control_origin` takes all non-dead control embryos. Which one produced the constants is not
recorded.

## Is it a meaningful control?

| Check | Result | Reading |
|---|---|---|
| Do wild-type-like genes (155, by the pipeline's own call) centre on the origin? | per-parameter mean position: median \|mean\| **0.09**, max 0.55; only **1 of 41** parameters above 0.5 | The origin does represent wild type; no systematic offset. |
| Distance to origin (median) | WT-like **2.60**, Dev. Delay **3.04**, Phenotype **6.51** | Phenotypes separate clearly from wild type. |
| Control embryo spread ÷ normalisation scale (`controlStd/rnaiStd`) | median **0.72** (range 0.10–2.31); **31 of 41** above 0.5, **11 of 41** above 1 (highest: `CoM1GavgRes_MS` 2.31, `CoM1RavgRes_MS` 2.05, `CoM0RavgRes_MS` 1.86, `MoI1GstdTail_MS` 1.71, `tailLength_MS` 1.69) | On many parameters, ordinary embryo-to-embryo variation of a single control embryo is as large as the differences between knockdowns. (Gene values are medians of several embryos, so their noise is smaller than a single embryo's.) |
| Noise floor: spread of WT-like genes per parameter | median **0.34** units | 0.34 × √41 ≈ 2.2, close to the 2.6 median distance of WT-like genes: their distance from the origin is mostly noise. |

**Consequence for PAD.** For two noise-only vectors, d(A,B) ≈ √2 × 2.2 ≈ 3.1 and the denominator ≈ 2 × 2.2, so
PAD ≈ 0.3. That is where the bulk of every gene's PAD distribution sits (see the histogram in
`notebooks/walkthrough.ipynb`). PAD is informative for genes clearly away from wild type and noise-dominated near
it. The pipeline partly accounts for this (matches need PAD > 0.5 / 0.55; WT-like genes get "do not exhibit an
arrest phenotype" instead of reciprocal matches), but `top_hits_PAD` is still filled in for WT-like genes.

## Does going parameter by parameter create artificial phenotypes?

| Where | Verdict | Why |
|---|---|---|
| **Per-gene medians**, parameter by parameter | **Real concern; untestable with public data** | Each parameter's median is taken independently, sometimes over different embryos (per-parameter fit checks), so a gene's vector can describe a "median embryo" that never existed. Most likely with incomplete penetrance (e.g. half the embryos arrest early, half late). The non-moving-only rule deliberately selects the penetrant subset. Testing this needs the per-embryo `embryos` table, which is not in the Zenodo record (LAB_QUESTIONS #12). |
| **Group centroids** (auto-descriptions) | **Literally constructed phenotypes** | `getAvgVector` / `getNDAvgVector` average group members coordinate by coordinate (`nanmean`, so different members can contribute different parameters). A centroid can sit between dissimilar members and resemble none; groups of 3–4 genes make this fragile. The elt-1 duplicate in `dorsRupt` (A17) adds to it. |
| **Per-parameter normalisation** | Standard; does not create phenotypes | A linear rescaling: it only sets how much each axis counts. Scaling by the RNAi spread (not control spread) is the authors' choice. |
| **Independent axes** (plain Euclidean distance) | Some double-counting, not severe | Correlated parameters count more than once. Across the 503 genes: median pairwise \|r\| **0.15**, only **3 of 820** pairs above 0.8; PCA: first 1/3/5/10 components hold 22/41/52/70% of the variance, effective dimensionality (participation ratio) ≈ **12** of 41. |

Other limitations: one pooled control rather than imaging-date-matched controls (batch effects are not
modelled); the origin is a mean of embryos while genes are medians (minor, given the centring result).
